## 1. ส่วนที่เสร็จสมบูรณ์

### ฐานข้อมูลและ REST API — 100%

86 endpoint แบ่งเป็น 12 โมดูล · 19 ตาราง พร้อมความสัมพันธ์และข้อจำกัดครบ
เอกสาร API สร้างอัตโนมัติที่ `/docs`

โมดูลที่ซับซ้อนที่สุดคือ `bookings.py` (16 endpoint) ซึ่งคำนวณช่องเวลาว่างจาก
เวลาเปิด-ปิดร้าน · ตารางงานของผู้ให้บริการรายคน · วันหยุดประจำสัปดาห์ ·
วันหยุดเฉพาะกิจ · คิวที่ถูกจองไปแล้ว · และเพดานการจองล่วงหน้า

### ส่วนติดต่อผู้ใช้ — 100%

20 หน้า รองรับ 3 บทบาท

| บทบาท | ทำอะไรได้ |
|---|---|
| ลูกค้า | ค้นหา · ดูรีวิว · จอง · ชำระมัดจำ · เลื่อนนัด · ยกเลิก · รีวิว · เปิดก๊วน |
| เจ้าของร้าน | เปิดร้าน · จัดการบริการและช่าง · ดูคิว · ประกาศวันหยุด · รายงานยอดขาย |
| ผู้ดูแลระบบ | จัดการผู้ใช้ · รับรองร้าน · ดูภาพรวมระบบ |

### การจองคิว — 100%

- แสดงช่องเวลาว่างจริง ไม่ใช่ตารางตายตัว
- เลือกผู้ให้บริการรายคนได้ หรือให้ร้านจัดให้
- ผังทรัพยากร × เวลา สำหรับสนามและคอร์ท เห็นทั้งวันในหน้าเดียว
- ช่องเวลาถูกล็อกเมื่อชำระมัดจำแล้วเท่านั้น — ใครชำระก่อนได้ก่อน
- เพดานจองล่วงหน้า 90 วัน บังคับทั้งฝั่งเซิร์ฟเวอร์และหน้าเว็บ
- เกณฑ์อายุขั้นต่ำรายหมวด (สักลาย 20 ปี · คลินิก 18 ปี) ตรวจที่วันเข้ารับบริการ

### ความปลอดภัย — 98%

| ทำแล้ว | รายละเอียด |
|---|---|
| แฮชรหัสผ่าน | bcrypt พร้อมค่าสุ่มประจำบัญชี · กันรหัสถูกตัดที่ 72 ไบต์ |
| โทเคน | JWT HS256 มีวันหมดอายุ · มีบัญชีดำเมื่อออกจากระบบ |
| กันเดารหัส | 8 ครั้งต่อ 5 นาที ต่อคู่ (ชื่อผู้ใช้ + ไอพี) |
| กุญแจ JWT | เก็บถาวรในฐานข้อมูล ผู้ใช้ไม่หลุดตอนเซิร์ฟเวอร์ตื่น |
| ลืมรหัสผ่าน | โทเคนเก็บเป็นแฮช · อายุ 30 นาที · ใช้ได้ครั้งเดียว |
| ตอบเหมือนกันทุกกรณี | หน้าลืมรหัสผ่านไม่บอกว่าอีเมลนี้มีในระบบหรือไม่ |
| CORS | ปิด `allow_credentials` เพราะระบบใช้ header ไม่ใช่คุกกี้ |
| จำกัดการสมัคร | เปิดบัญชีจากไอพีเดียวกันรัว ๆ ไม่ได้ กันสคริปต์สร้างคิวผี |
| ส่วนหัวความปลอดภัย | `X-Content-Type-Options` · `X-Frame-Options` · `Referrer-Policy` · `Permissions-Policy` · HSTS เมื่อเข้าผ่าน https |
| อัปโหลดรูป | ตรวจไบต์จริงต้นไฟล์ ไม่เชื่อนามสกุล · เข้ารหัสรูปใหม่ทุกครั้งเพื่อลบสคริปต์ที่แนบมาและ EXIF ที่มีพิกัด GPS |

**ที่ยังขาด 2%** — ยังไม่มีการยืนยันอีเมลตอนสมัคร และยังไม่ได้ตั้ง `JWT_SECRET`
เป็น environment variable บนเว็บจริง (ใช้กุญแจถาวรจากฐานข้อมูลแทน ซึ่งใช้งานได้
และผู้ใช้ไม่หลุดล็อกอิน แต่ถ้ากุญแจอยู่นอกฐานข้อมูลจะแยกความเสี่ยงได้ดีกว่า)

### การทดสอบ — 95%

ผ่านทั้งหมด ไม่มีข้อที่ถูกข้าม

```
tests/test_booking_payment.py   121 ข้อ   ยิง REST API จริงบน SQLite ชั่วคราว
tests/test_shop_status.js        22 ข้อ   ตรวจตรรกะเวลาเปิด-ปิดฝั่งหน้าเว็บ
```

ชุดที่สองมีอยู่เพราะเคยเจอบั๊กจริง — หน้าเว็บขึ้น "ปิดแล้ววันนี้" ให้ร้านคาราโอเกะ
ที่เปิดถึงตีสอง ทั้งที่เซิร์ฟเวอร์ยอมให้จอง ชุดนี้จึงเทียบผลของสองฝั่งทีละชั่วโมง
ครบ 144 ช่วงเวลา × 3 รูปแบบร้าน

**ที่ยังขาด 5%** — ยังไม่มีการวัดความครอบคลุมของโค้ด และยังไม่มี CI ที่รันเทสต์อัตโนมัติตอน push

## 2. ส่วนที่ยังไม่เสร็จ

### ระบบชำระเงิน — 60%

**ทำแล้ว** — ขั้นตอนครบทั้งกระบวนการ มัดจำ 20% · ยอดคงเหลือ · คืนเงิน ·
หักมัดจำเมื่อลูกค้ายกเลิกเอง · ไม่หักเมื่อร้านยกเลิก · ใบเสร็จ · รายงานยอดขายของร้าน

**ยังไม่ได้ทำ** — ยังไม่ต่อกับผู้ให้บริการชำระเงินจริง การกดยืนยันเป็นการบันทึกยอด
ไว้ในระบบเพื่อล็อกคิวเท่านั้น เงินไม่ถูกตัดจากบัญชีผู้ใช้

**สิ่งที่ต้องทำต่อ** — ต่อ Omise หรือ Stripe (รองรับพร้อมเพย์ทั้งคู่) ·
รับ webhook ยืนยันการชำระเงิน · เก็บ log ธุรกรรมแยกสำหรับตรวจสอบย้อนหลัง

### การนำขึ้นใช้งาน — 98%

**ทำแล้ว** — เว็บเปิดใช้งานจริงบน Render ต่อฐานข้อมูล PostgreSQL บน Neon
มี HTTPS · มีหน้า 404 · มีแท็กแชร์ลิงก์รายร้านที่เรนเดอร์ฝั่งเซิร์ฟเวอร์

**แก้แล้วในรอบนี้**

| ปัญหาเดิม | แก้อย่างไร |
|---|---|
| รูปที่อัปโหลดหายทุกครั้งที่เครื่องหลับแล้วตื่น | ย้ายไบต์ของรูปไปเก็บในฐานข้อมูล ซึ่งเป็นที่เดียวในระบบนี้ที่ข้อมูลอยู่ถาวรจริง |
| Auto-deploy ของ Render ไม่ทำงาน ต้องกดเองทุกครั้ง | เพิ่ม GitHub Actions ที่ยิง deploy hook ให้อัตโนมัติทุกครั้งที่ push |

**ยังเหลือ**

| ปัญหา | ผลกระทบ | ทางแก้ |
|---|---|---|
| เซิร์ฟเวอร์หลับเมื่อไม่มีผู้ใช้ | เปิดครั้งแรกรอ 30–60 วินาที | ข้อจำกัดของแพ็กเกจฟรี ต้องอัปเกรด |

### ข้อมูลในระบบ

ร้านและสนาม 38 แห่งเป็นข้อมูลตัวอย่างที่สร้างจากสคริปต์ มีร้านจริง 1 ร้าน
ที่ผู้ใช้ภายนอกสมัครและเปิดเอง เว็บระบุไว้ชัดเจนในหน้าเงื่อนไขการใช้งานและส่วนท้ายทุกหน้า
